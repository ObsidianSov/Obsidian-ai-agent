## Known gaps (not done)

- M6 limits: code a script imports from other folders/packages is not inspected; `npm run`, `make`, `pip install` (setup.py) and `python -m <not a workspace file>` are not covered; the shell parser can be fooled by `$(...)`, aliases, functions. It only helps if you read the code in the prompt. `ai.py` runs its chat loop on import, so it is tested by reading its source and by running the real `gated_run_command` with stubs, not by running the full agent.
- `fetch_url`: DNS rebinding not closed (name validated, then re-resolved at connect time). No response size cap.
- Blueprint layers not built: Planner (v1 plan is free text the model writes), Recovery, Learning. Task Engine has the first two steps (INSPECT lock + plan approval); Verification has v1 only (M9, limits below).
- Agent memory is only what is in `workspace/memory/memories.json`. It does not know who its owner is; the old owner-profile loading went away with `agent_core`. (Parked on purpose.)
- Task Engine v1 limits: after you approve a plan, nothing checks that the agent's later writes match it (ACT is unrestricted apart from the gates); the read-only command list is deliberately short, so some harmless commands wait for plan approval; a live check with a real model passed for `yes` and `/do` (see M8), but a plan rejected with `no` and typed feedback have not been seen live.
- Verify v1 limits: only files written with `write_file` are tracked (files made by commands such as `cp`, `git`, `npm install` are not). It proves a check RAN and PASSED, not that it was a good check: a model can run a trivial script that exits 0. A check is matched to a file by name, so two files with the same name in different folders can be confused. A build of many non-code files costs one `read_file` per file against the 15-round limit. If the model never checks, its answer is still shown after 2 tries, with the NOT VERIFIED notice. It is not stopped. Live check 2026-10-16: the model verified by itself. Live check 2026-10-17: the bounce path ran with a real model and worked. Gap found then: after you deny the check at the script gate, the model is still bounced a second time (a wasted request); planned for the Recovery milestone.
- No safe tool for looking inside a zip archive (the agent can only try shell commands).
- Not tested by anything automatic: the model itself (OpenRouter), real internet beyond `fetch_url`, and the model's judgement. Those are checked by hand on the phone.
- Default model in `ai.py` is `minimax/minimax-m2.7` (paid). The phone overrides it via `OBSIDIAN_MODELS` (banner shows `openrouter/free`). If that variable is not set in a new Termux session, the paid default is used.
- RainCast and `agent_core` are removed from the repo but still in git HISTORY on GitHub. If the repo is public and that work is private, history would need rewriting (not done).
